# chauth: ClickHouse access through temp users, on both protocols

chauth lets people and programs reach ClickHouse with a short-lived OIDC access token instead of a database password. It verifies the token, decides access from `ChRole` / `ChRoleBinding` rules capped by the token's scope, and logs in upstream as a temp user that holds exactly the upstream roles the rules give.

For each holder, level and role set, a process creates a temp user `<prefix><sub8>_<nonce><rand6>` with `VALID UNTIL`, optional `HOST IP`, `SETTINGS log_comment = '<user>' CONST` (plus `readonly = 2 CONST` at read level) and those roles, hands it out for at most `leaseDuration`, and drops it after its last use; a sweep drops expired temp users of any process. A per-person upstream identity makes `system.query_log` attributable and lets ClickHouse, not the proxy, enforce every grant. `log_comment` is CONST because both protocols let a client set it; the native protocol lets a client set `quota_key` and `client_hostname`, so those are never trusted.

The admin login holds only `CREATE USER, DROP USER ON <prefix>*`, `SELECT ON system.users` and the chauth roles `WITH ADMIN OPTION`. It deliberately has no `ALTER USER`: `ALTER USER <prefix>x RENAME TO <anything>` passes the prefix check and moves a user out of it. What remains is that the admin can grant or revoke its roles on any existing user, so its credentials belong to the proxy alone.

Both protocols are proxied. On the native port the token is the Hello password; chauth reads only the client Hello (capped at 64 KiB), refuses the interserver and SSH-key user markers, rewrites user, password and database, keeps the client's name, version and revision, then copies bytes both ways. Most ClickHouse clients, `clickhouse-client` first, speak only native. On HTTPS every request is verified on its own and sent upstream with Basic auth as the temp user, after removing every client credential and `quota_key` in any letter case; HTTP sessions (`session_id`) are refused because a `SET ROLE` earlier in a session would outlive the request's decision. A native connection is checked when it opens and cut after `maxConnectionAge`; it keeps running after its token expires, so a revoke stops new connections and requests at once and open native connections at the cut.

Grants name a database (`{instance, database, level}`, mapped to an upstream role by `roleTemplate`) or an upstream role by name (`{instance, role, level}`), which must be in the instance's `roles` allowlist. Table-, column- and row-policy-level roles are defined upstream in infrastructure-as-code and granted by name, so the proxy never invents grants. A ClickHouse query can name any database, so the temp user holds every role the holder reaches on the instance, and the target database is only the session default. A database listed in `readOnlyDatabases` (such as `system`) yields only its read role for any grant, so a write grant on `*` does not need a write role there.

Rejected: two shared upstream users with roles chosen per request (no per-person identity, HTTP only, and the database boundary would rest on parameter handling); HTTP only (most clients are native-only); ClickHouse Cloud's native JWT login (enterprise tier only, and roles come from a token claim, so neither these bindings nor the scope cap could be expressed).
