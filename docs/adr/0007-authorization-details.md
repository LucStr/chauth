# Tokens narrow access with authorization_details; run tables are granted directly

Role bindings say the most a person may reach, and the scope caps it at read or write for every database at once. A token can now say less: the `authorization_details` claim (RFC 9396, type `clickhouse`) holds consent rows (`identifier` `*` or a database, `actions` read or write) and run rows (a database with `tables` and verbs). Access is bindings ∩ scope cap ∩ consent rows ∩ run rows, so a row never adds anything, and the bindings stay the ceiling ([0002](0002-authorization-as-code.md)). The issuer decides which rows a token carries; chauth only reads them, so nothing deployment-specific enters the code ([0003](0003-nothing-deployment-specific.md)).

The claim fails closed. An unknown field in a row refuses the token, so a restriction the issuer adds later can never be silently ignored by an older chauth; a database without a row is not reached; a token without the claim gets exactly what it got before. The identifier is the bare database name, applied on every instance that serves it, because the issuer knows audiences, not instances.

A run row's tables are granted to the temp user directly (`SELECT`, `INSERT`, `ALTER UPDATE`, `ALTER DELETE ON db.table`) and the database's template roles are left out. Write roles today hold DDL as well as DML, so a role per verb would either carry DDL or need four new roles per database upstream; direct grants carry exactly the declared verbs, need no upstream object per table, and go away when the temp user is dropped ([0001](0001-temp-users-both-protocols.md)). The cost is that the admin holds `SELECT, INSERT, ALTER UPDATE, ALTER DELETE ON <db>.* WITH GRANT OPTION`; it already holds the database roles as default roles, so this widens what it can hand out, not what it can reach. The self-test grants them so a missing grant shows as not ready, not as failed connections.

Named roles are no database, so only the `*` row speaks for them: they follow its level and are dropped without one. Table rows on a read-only database give nothing, so the admin never needs grant options on `system`.

Rejected: one upstream role per table and verb (an upstream object per table, created by a proxy that is meant never to invent grants); enforcing the declared tables by parsing queries (the proxy never reads query text, and ClickHouse already enforces grants).
